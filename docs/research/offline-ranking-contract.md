# 离线候选评分接口草案

[← 项目首页](../../README.md) · [架构](../ARCHITECTURE.md) · [路线图](../ROADMAP.md)

这是一份研究设计草案，约定如何比较已有候选的评分方法。它尚未作为公开版本的功能提供，生产上下文排序保持关闭；当前 Alpha 包不包含模型。接口设计和轻量测试不能证明排序收益、缓存数值等价或实际输入延迟。

## 评分对象

输入引擎先产生候选，评分器只比较调用方提供的文本。它不解码拼音、不补造缺失候选，也不改写候选的原始身份。研究输入使用已批准的合成文本；真实用户前文、词库、诊断记录和私人文档不作为公开测试素材。

| 字段 | 约定 |
| --- | --- |
| 输入与 preedit | 保留引擎实际接收到的键和当前编辑文本，不能从目标答案反推 |
| 候选身份 | 每个候选保留原始 `source_index`、文本及完整提交结果；重排后仍可映射回同一候选 |
| 引擎事实 | 完整键覆盖、可信词典来源等事实由引擎证据提供；无法证明时保留“未知” |
| 前文 | 标明合成来源与允许使用的范围；缺失前文时保持原排序 |
| 生命周期 | 用不含用户内容的临时标识区分字段、编辑版本和实验会话 |
| 词典版本 | 只有能证明当前运行时版本时才填写有效 epoch；磁盘文件版本不能替代运行时证据 |
| 模型配置 | 固定来源、版本、文件摘要、运行时和评分方式，使比较可复现 |

目标答案、分组、歧义词对和 train/dev/test 标签属于评估侧信息。它们应与模型请求分开，不能因存放在“输入文件”中就一并交给评分器或教师模型。

## 输出与失败处理

评分结果必须与本次请求的候选身份一一对应，分数为有限值。条件分数及相对无前文的分数差应分别报告；它们不能直接当作校准后的置信度。相同分数保留原顺序，拒绝、超时或无有效结果时保留引擎首选。

只有引擎证据和上下文范围均满足约定时，才可研究是否干预排序。可信词典首选、敏感字段、来源未知、无法证明完整提交或过长候选等情况需要明确的拒绝策略。不能按目标答案长度筛候选，也不能把未召回的答案插入池中。

缓存只属于一个明确的生命周期与所有者。字段切换、编辑失效和该所有者的失败路径必须退役旧状态；并发调用被拒绝时不能清除另一个正在工作的所有者。过期回复不能提交到新输入状态。释放缓存引用与安全擦除内存是不同保证，文档应说明实际提供的范围。

模型加载和评分留在独立研究进程中，不能进入 TIP 的按键处理路径。调用方必须限定输入大小、候选数量、内存和整进程墙钟预算；单次模型调用计时或合作取消不能代替这些约束。

## 验证门槛

- 先验证候选身份、完整提交和字段范围，再计算排序指标。
- 固定评估分母，保留未召回、拒绝和失败项；分别报告纠正、破坏原首选、错到错变化，以及应拒绝却干预的情况。
- train/dev/test 按歧义家族及所有输入别名隔离，规范输入和实际输入也需要交叉检查。
- 独立重算、前缀缓存和批量评分需要在相同候选上验证数值与选择结果；验证失败时不能发布对应优化的性能结论。
- 模型前向、引擎、IPC、宿主提交和界面显示分别计时；离线计时不能冒充完整输入法延迟。
- 合成单元测试、真实引擎验证和 Windows 宿主验收分别记录范围，不相互替代。

当前仓库的基础 CI 使用 `ZILIU_ENABLE_RIME=OFF`，不覆盖这些模型、真实引擎或宿主验证。研究源码是否适合合并，需要独立审查与可复核的验证结果。

## 来源与发布

采用外部实现、运行时或模型前，应分别核实源码、权重与训练语料的来源和许可，保留适用的 LICENSE、NOTICE 与归属。文件摘要证明的是文件身份，元数据中的许可标签不能替代完整的许可核实。

公开交付应限于审核过的第一方源码、合成边界测试和脱敏协议。模型权重、下载缓存、冻结评估样本、原始证据及私人测量结果需要单独的发布范围和许可确认。主项目现有许可证不替换第三方条款，见[第三方声明](../../THIRD_PARTY_NOTICES.md)。

后续先完善证据和生命周期边界，再比较评分方法，最后评估是否存在可部署的收益；此草案不承诺完成日期或模型效果。
