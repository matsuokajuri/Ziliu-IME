# 字流架构

## 设计目标

字流是本地优先的 Windows 输入法。任何被加载进宿主应用的代码都必须体积小、无网络、
无磁盘数据库写入、无长时间阻塞，并能在后台进程不可用时安全放行按键。

## 进程边界

```text
Windows 应用
  └─ ZiliuTIP.dll             TSF、组合文本、焦点和按键边界
       └─ ZiliuCandidate UI   当前宿主拥有的轻量候选窗
             │
             └─ 本机命名管道（后续）
                    │
                    └─ ZiliuBroker.exe
                         ├─ librime
                         ├─ 雾凇拼音只读系统词库
                         └─ 本地用户词库

ZiliuSettings.exe ── 配置文件/受版本控制的 Broker API
```

### ZiliuTIP.dll

- 原生 COM in-process DLL。
- 只实现 TSF 协议、按键状态、编辑会话和候选窗定位。
- 不直接链接网络库，不持有用户数据库，不加载大词库。
- Broker 失联时必须结束组合并放行输入。
- 未来分别构建 x64、x86、ARM64，代码与接口保持一致。

### ZiliuBroker.exe

- 每用户、每会话一个实例。
- 使用阻塞消息/IO 等待，空闲时不轮询。
- 独占 librime 会话和用户词库写入，避免多个宿主进程争用数据库。
- IPC 采用带版本号的本机命名管道，ACL 限制为当前用户 SID。

### ZiliuSettings.exe

- 纯原生 Win32 + Direct2D/DirectWrite。
- 不常驻；关闭设置窗口后进程退出。
- 通过原子替换写入版本化配置，并通知 Broker 热加载。

## 数据边界

- 程序文件与只读词库存放在安装目录。
- 用户设置和用户词库存放在 `%LocalAppData%\Ziliu`。
- 雾凇拼音作为独立、可追溯的 GPL 数据依赖引入。
- 字流定制通过 overlay 文件实现，不直接改写上游词库。
- 当前阶段不存在云同步模块或网络访问。

## 失败策略

1. TIP 初始化失败：返回错误，宿主继续使用普通键盘输入。
2. Broker 不存在：异步启动；启动前不吞键。
3. Broker 超时：立即放弃当前请求，不在按键回调中重试。
4. 引擎崩溃：Broker 重启后创建新会话；不尝试恢复未上屏文本。
5. 配置损坏：保留损坏文件，加载最后已知有效配置或内置默认值。

## 性能预算

- TIP 每宿主进程私有内存目标：小于 10 MiB。
- Broker 空闲 CPU：接近 0。
- 热状态本机 IPC P95：小于 2 ms。
- 按键到候选刷新 P95：小于 16 ms。
- 设置程序、更新程序和未来同步程序都不常驻。
